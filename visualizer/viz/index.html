MCP: the same search, as a tool for an agent

Nobody inside the project calls the MCP server: a client starts it. The client reads the launch command from its own config, starts python -m src.extra.mcp_server as a child process and writes JSON-RPC lines to its stdin; replies come back on stdout. Here the engine plays that client against the real server, and every line that crossed the pipe is replayed below.

model picks a tool→client→stdin · JSON-RPC→server src/extra/mcp_server→RagTools → BM25 index→stdout · result→model reads it, maybe searches again
Uses the question and k from the bar above. The session is real: handshake, tools/list, search_vllm, read_source around the first hit, then a bad call to show how errors reach the model.
